# بررسی و بهبود مدیریت مالی شخصی

تاریخ: ۲۰۲۶/۱۱/۱۳. مبنا: کد مخزن در commit `cf40a26`، اجرای محلی و دادهٔ آزمایشی؛ این گزارش ممیزی کامل امنیتی یا تأیید سرویس مستقر نیست.

## نتیجه بررسی

زیرساخت فعلی شامل حساب‌ها، ثبت و ورود تراکنش، بودجه شمسی، وام/چک/قبض، طلب و بدهی اشخاص، اهداف تورمی، سرمایه‌ها، کسب‌وکار و ابزارهای بازار است. برای مدیریت روزمره، کمبود اصلی داشبورد این بود که ارزش دارایی با توان پرداخت اشتباه گرفته می‌شد و پیش‌بینی نقدینگی موجود فقط سررسیدها را لحاظ می‌کرد. درآمد عقب‌افتاده هم می‌توانست همان امروز وصول‌شده فرض شود.

## تغییرات این نسخه

- برنامه نقدینگی ۳۰ و ۹۰ روزه در صفحه اصلی؛ محاسبه کاملاً روی دستگاه، بدون API یا ارسال دفتر مالی.
- پیش‌فرض محافظه‌کارانه بدون دریافت جدید، همراه سناریوی اختیاری دریافت به‌موقع.
- موجودی قابل پرداخت از بانک، نقد و کیف پول شخصی؛ بدون حساب کسب‌وکار، صندوق، صرافی، مطالبات و ارزش فروش‌نرفته سرمایه‌ها.
- تاریخ اولین کسری، کمترین موجودی و مبلغ لازم برای پوشش کسری، پرداخت‌های آتی و مانده پایان دوره.
- برآورد هزینه روزانه از سابقه حداکثر ۹۰ روز، بدون پرداخت‌های متصل به اسناد؛ نمایش هشدار برای سابقه کمتر از ۳۰ روز.
- نمودار با خط صفر، جدول روزانه قابل دسترسی، کنترل‌های دارای برچسب، نمایش راست‌به‌چپ و اندازه‌های موبایل.
- هشدار «بدهی عقب‌افتاده» فقط برای خروج پول؛ طلب و حقوق عقب‌افتاده دیگر بدهی نامیده نمی‌شوند.
- مبلغ ماهانه هدف در داشبورد از همان رشد قیمت کالا استفاده می‌کند که صفحه اهداف استفاده می‌کند.

## تعریف مالی و محدودیت‌های محاسبه

اعداد داخلی ریال و نمایش تومان است. موجودی ابتدای برنامه از دفتر تا امروز گرفته می‌شود؛ تراکنش و گزارش بانکی با تاریخ آینده موجودی امروز را افزایش نمی‌دهند. پرداخت معوق امروز در نظر گرفته می‌شود؛ دریافت معوق در هیچ سناریویی وارد موجودی نمی‌شود. پس از وصول واقعی، ثبت دریافت موجودی را اصلاح می‌کند.

هر نقطه، مانده پایان آن روز است؛ ترتیب پرداخت و دریافت درون روز معلوم نیست. کسری ممکن است پیش از دریافت همان روز رخ دهد. مجموع حساب‌ها بررسی می‌شود، نه کفایت موجودی حساب صادرکننده چک. سرمایه‌های نقدشونده فقط پس از ثبت انتقال به حساب قابل پرداخت محسوب می‌شوند.

برآورد خرج روزمره، هزینه‌های شخصی بدون `link` را بر بزرگ‌ترِ ۳۰ و تعداد روزهای سابقه تقسیم می‌کند. پرداخت‌هایی که بدون اتصال به سند دوباره ثبت شده‌اند می‌توانند باعث دوباره‌شماری شوند؛ پرداخت‌ها باید از مسیر تسویه سند ثبت شوند. سابقه کوتاه یا ناقص تخمین را خوش‌بینانه می‌کند. تورم آینده هزینه‌ها، اهداف پس‌انداز، بازده سرمایه‌گذاری و تراکنش‌های تاریخ‌آینده در پیش‌بینی نیستند؛ برنامه، تضمین توان پرداخت یا توصیه خرید دارایی نیست.

## اولویت‌های باقی‌مانده برای استفاده بلندمدت

| اولویت | مشاهده در کد | اقدام پیشنهادی |
| --- | --- | --- |
| بالا | `FinanceProvider.read` در خرابی JSON به دفتر خالی برمی‌گردد؛ ذخیره بعدی می‌تواند نسخه خراب را جایگزین کند | قرنطینه نسخه خراب، حالت بازیابی و آزمون بازیابی قبل از نوشتن جدید |
| بالا | دفتر در localStorage است؛ پشتیبان JSON دستی و بدون رمزگذاری است | پشتیبان رمزگذاری‌شده با بازیابی آزموده‌شده؛ همگام‌سازی چنددستگاهی فقط پس از طراحی احراز هویت و حل تعارض |
| بالا | `normalizeData` آرایه‌های مهم را عمدتاً بدون اعتبارسنجی هر رکورد می‌پذیرد | اعتبارسنجی مبلغ متناهی، تاریخ، شناسه، مرجع حساب و سقف اندازه فایل در ورودی |
| متوسط | سقف روزانه مشاور با `get` و سپس `set` کنترل می‌شود | شمارنده اتمی و محدودیت هم‌زمانی برای جلوگیری از عبور درخواست‌های موازی از سقف |
| متوسط | `isAdmin` رمز را در query string هم قبول می‌کند | مهاجرت فراخوانندگان به header و حذف رمز از URL؛ بررسی سازگاری قبل از حذف |
| متوسط | طرح نقدینگی به کامل بودن ثبت‌های دستی وابسته است | نشانگر پوشش داده، کنترل مانده هر حساب و تطبیق هزینه‌های بی‌سند با قبض و قسط |
| بعدی | اهداف، تورم و بودجه جداگانه موجودند | برنامه تخصیص ماهانه مشترک برای صندوق اضطراری، بازپرداخت بدهی و اهداف بدون دوباره‌شماری پس‌انداز |

این موارد عمداً به‌عنوان کار انجام‌شده گزارش نشده‌اند. افزودن اتصال بانکی واقعی، دریافت خودکار داده معتبر و همگام‌سازی ابری نیازمند سرویس و طراحی مستقل است.

## روش آزمون

- `npm run typecheck`
- `npm run build`
- `node --import tsx scripts/planning-test.ts`
- `node --import tsx scripts/finance-test.ts`
- `node --import tsx scripts/finance-plus-test.ts`
- `node --import tsx scripts/goal-price-test.ts`
- `node --import tsx scripts/ui-test.ts`

آزمون‌های برنامه نقدینگی شامل دفتر خالی، تفکیک پول شخصی، تاریخ آینده، هزینه روزمره، پرداخت متصل به قبض، دریافت معوق، چک وصول‌شده، مرز ۳۰ روز، بدهی اشخاص و تغییرنکردن داده ورودی هستند. سرویس‌های زنده بازار، مشاور خارجی و APK اندروید در محدوده این آزمون نیستند.

نتیجه اجرای این نسخه: ۴۴ بررسی خودکار در پنج مجموعه بالا، TypeScript و build موفق بودند. در Chromium با اندازه‌های ۱۴۴۰×۱۰۵۰ و ۳۹۰×۸۴۴، دفتر خالی، خواندن دفتر ذخیره‌شده، تغییر سناریو، بازه ۹۰ روزه و ۹۱ ردیف جدول، نبود اسکرول افقی، رفت‌وبرگشت به بودجه و ثبت هزینه ۱۰۰٬۰۰۰ تومانی (ذخیره به‌صورت ۱٬۰۰۰٬۰۰۰ ریال) و باقی‌ماندن آن پس از بارگذاری مجدد بررسی شد. خطای JavaScript صفحه ثبت نشد. هشدار موجود Next.js درباره مهاجرت `middleware` به `proxy` باقی است.
