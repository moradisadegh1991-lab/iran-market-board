# پلاگین بومی خواندن پیامک

> ⚠️ **روی گوشی واقعی هنوز تست نشده.** از مهر ۱۴۰۵ همه این کد با Android SDK کامپایل می‌شود (APK در CI و محلی) و مسیر اعلان
> با ۱۳ تست Robolectric (کلاس‌های واقعی فریم‌ورک اندروید روی JVM) سنجیده شده؛ ولی رفتار گوشی واقعی (بهینه‌سازی باتری سامسونگ،
> heads-up در One UI، پیامک بانک‌های واقعی) فقط روی گوشی دیده می‌شود.

## فایل‌ها

| فایل | کار |
|---|---|
| `java/SmsReaderPlugin.java` | پلاگین Capacitor: خواندن صندوق پیامک، مجوزها، و پل اعلان (`asked`، `clearAsked`، `setAsk`، `launchRoute`، رویدادهای `smsChoice` و `route`) |
| `java/BankSms.java` | همان طبقه‌بند `www/sms-parser.js` به Java، تا گوشی با اپ بسته تصمیم بگیرد؛ `npm run test:nativesms` برابری‌شان را قفل کرده |
| `java/SmsAsk.java` | ذخیره پیامک‌هایی که پرسیده شده‌اند و جوابشان (SharedPreferences)، و ساختن اعلان «نوعش چیست؟» |
| `java/SmsAskReceiver.java` | گیرنده `SMS_RECEIVED` — اندروید با اپ بسته هم صدایش می‌زند |
| `java/SmsChoiceReceiver.java` | لمس دکمه اعلان: ذخیره جواب و تبدیل اعلان به «✓ هزینه» که خودش می‌رود |
| `test/BankSmsCli.java` | راه‌انداز تست برابری Java و JS (وارد اپ نمی‌شود) |
| `test/robolectric/SmsAskTest.java` | تست‌های اندرویدی؛ `scripts/wire-native-tests.mjs` در پروژه می‌گذاردشان |

## چرا منطق در JS است

پلاگین متن خام پیامک‌ها را برمی‌گرداند و تشخیص تراکنش، مبلغ، بانک و دسته همه در جاوااسکریپت است. تنها استثنا تصمیم «این پیامک
بانکی است و جهتش چیست» برای اعلان است که باید با اپ بسته گرفته شود؛ برای همین `BankSms.java` نسخه خط‌به‌خط پارسر JS است و ردیفی
که در دفتر می‌نشیند همچنان با JS ساخته می‌شود.

فقط **می‌خواند**. نه ارسال، نه حذف، نه هیچ درخواست شبکه‌ای — متن پیامک‌ها از گوشی خارج نمی‌شود. گیرنده پخش پیامک را متوقف
نمی‌کند، پس اپ پیامک خود گوشی مثل همیشه پیام را نشان می‌دهد.

## نصب — خودکار

‌قبلاً این سه مرحله دستی بود (کپی فایل Java، ویرایش `MainActivity.java`، ویرایش مانیفست) — دقیقاً همان نوع کاری که یک خط اشتباه در آن اپ را بی‌صدا خراب می‌کند. حالا یک اسکریپت انجامش می‌دهد:

```bash
npx cap add android      # فقط بار اول
npx cap sync android
npm run wire-plugin       # کپی همه فایل‌های java/ + ثبت در MainActivity + مجوزها (READ_SMS، RECEIVE_SMS، اعلان) + دو گیرنده در مانیفست
```

‏workflow گیت‌هاب (`build-android.yml`) همین را خودش، خودکار، در هر بیلد اجرا می‌کند — نیازی به کار دستی نیست.

اسکریپت (`scripts/wire-native-plugin.mjs`) idempotent است: اجرای دوباره‌اش چیزی را تکراری نمی‌کند. با هر دو حالت واقعی `MainActivity.java` که Capacitor می‌سازد تست شده — وقتی اصلاً `onCreate` ندارد (پیش‌فرض Capacitor 6) و وقتی از قبل `onCreate` دارد (اگر پلاگین دیگری قبلاً چیزی به آن اضافه کرده). در حالت دوم، کد موجود دست‌نخورده می‌ماند.

اگر ترجیح می‌دهید دستی انجام دهید یا می‌خواهید ببینید اسکریپت چه می‌کند:

## استفاده از سمت JS

```js
const { SmsReader } = window.Capacitor.Plugins;
const { granted } = await SmsReader.requestPermission();
if (granted) {
  const { messages } = await SmsReader.read({ sinceMs: lastImport, limit: 500 });
  for (const m of messages) {
    const c = window.SmsParser.classify(m.body);
    if (c.kind === 'confirmed') { /* ثبت تراکنش */ }
    else if (c.kind === 'ambiguous') { /* از کاربر بپرس */ }
  }
}
```

## نکته مهم درباره انتشار

گوگل‌پلی مجوز `READ_SMS` را فقط برای اپ‌های پیش‌فرض پیامک تأیید می‌کند و اپ شما رد می‌شود. **مایکت و کافه‌بازار این محدودیت را ندارند** و مقصد شما همان‌هاست، ولی اگر روزی قصد گوگل‌پلی داشتید این بخش باید حذف شود.

## دو باگی که در پارسر اصلی پیدا شد

هنگام انتقال منطق از `SmsParser.kt` دو اشکال پیدا شد که در نسخه JS رفع شده‌اند و **در اپ ExpenseTracker هم باید رفع شوند**:

۱. **پیامک بلو، مانده را به‌جای مبلغ ثبت می‌کرد.** در «۵۰٬۰۰۰ ریال از حساب شما پرید. مانده: ۱٬۰۰۰٬۰۰۰» مبلغ *قبل* از کلیدواژه است، ولی `substringAfter` فقط بعد از کلیدواژه را می‌گشت و به مانده می‌رسید.

۲. **پیامک رمز پویا به‌عنوان تراکنش ثبت می‌شد.** `classify` اول `parse` را صدا می‌زد و بعد فیلتر اسپم را؛ چون پیامک رمز پویا مبلغ دارد («رمز پویا: ۸۴۲۱۳ مبلغ ۱٬۵۰۰٬۰۰۰ ریال»)، با موفقیت پارس می‌شد و به‌عنوان تراکنش قطعی ثبت می‌شد. بعد پیامک برداشت واقعی هم می‌آمد، یعنی **هر خرید کارتی دو بار شمرده می‌شد**. ضمناً «رمز پویا» و «رمز دوم» اصلاً در فهرست کلیدواژه‌های اسپم نبودند.
